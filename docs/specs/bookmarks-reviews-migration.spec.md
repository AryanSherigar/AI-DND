# Spec: Alembic Migration for `bookmarks` and `scenario_reviews`

## 1. Objective & User Outcome
- **Problem Statement:** `app/db/models/bookmark.py` (`Bookmark`) and `app/db/models/review.py` (`ScenarioReview`) are fully wired into `scenario_repo.py`, `scenario_service.py`, and `routers/scenarios.py` (`POST/GET /v1/scenarios/{id}/reviews`, `POST /v1/scenarios/{id}/bookmark`), and covered by `tests/routers/test_scenario_focus.py`. Neither table exists in `db/migrations/versions/001_initial_schema.py` or any later migration — every one of those code paths fails against a real database with `UndefinedTable`. Defining an ORM model never creates the table itself; some schema-creation step is unavoidable for this code to run at all.
- **User Story:** As a player using the Scenario Focus page, I want to bookmark a scenario and leave a review after 10 turns, and have both durably persist, so the feature that's already built in code actually works against a real database.
- **Note on scope (dev-only project, no production data):** since there's no environment with real data to preserve and no prior release of this schema to stay compatible with, this doesn't need a hand-authored, carefully-reviewed migration the way a production schema change would. The fastest correct path is `alembic revision --autogenerate`, which diffs the current DB against the ORM models (already correct) and writes the migration for you — this spec commits to that approach instead of hand-writing `op.create_table(...)` calls. If the local dev DB ever drifts into a broken state, dropping and recreating it via `alembic upgrade head` from scratch is also fine — there's nothing to lose.
- **Success Criteria:**
  - An Alembic migration (autogenerated) creates `bookmarks` and `scenario_reviews` matching the ORM models exactly.
  - `alembic upgrade head` succeeds from a clean database.
  - `tests/routers/test_scenario_focus.py` passes against a real (non-mocked) test Postgres instance.

## 2. Technical Architecture & Data Flow
- **Components Involved:** `apps/core-api/app/db/migrations/versions/` (new migration file only). No application code changes — the ORM models are already correct; only the schema is missing.
- **Sequence Flow:** `alembic revision --autogenerate -m "bookmarks and scenario_reviews"` diffs the ORM metadata against the live dev DB and generates `002_bookmarks_and_reviews.py` → review the autogenerated `upgrade()`/`downgrade()` for sanity (autogenerate sometimes misses server-side check constraints — confirm `ck_scenario_reviews_rating` made it in; add manually if not) → `alembic upgrade head`.

### 3.4. Code Style & Interfaces
The block below is a reference for what `alembic revision --autogenerate` should produce — don't hand-type it; run the command and diff the output against this shape, fixing anything autogenerate got wrong (most commonly: missing `CheckConstraint`s, since some autogenerate configurations don't detect those).
```python
"""bookmarks and scenario_reviews tables

Revision ID: 002_bookmarks_and_reviews
Revises: 001_initial_schema
Create Date: ...
"""

from alembic import op
import sqlalchemy as sa
from sqlalchemy.dialects import postgresql

revision = "002_bookmarks_and_reviews"
down_revision = "001_initial_schema"


def upgrade() -> None:
    op.create_table(
        "bookmarks",
        sa.Column("bookmark_id", postgresql.UUID(as_uuid=True), primary_key=True),
        sa.Column(
            "user_id",
            postgresql.UUID(as_uuid=True),
            sa.ForeignKey("users.user_id", ondelete="CASCADE"),
            nullable=False,
        ),
        sa.Column(
            "scenario_id",
            postgresql.UUID(as_uuid=True),
            sa.ForeignKey("scenarios.scenario_id", ondelete="CASCADE"),
            nullable=False,
        ),
        sa.Column("created_at", sa.TIMESTAMP(timezone=True), server_default=sa.text("now()"), nullable=False),
        sa.UniqueConstraint("user_id", "scenario_id", name="uq_bookmarks_user_scenario"),
    )

    op.create_table(
        "scenario_reviews",
        sa.Column("review_id", postgresql.UUID(as_uuid=True), primary_key=True),
        sa.Column(
            "scenario_id",
            postgresql.UUID(as_uuid=True),
            sa.ForeignKey("scenarios.scenario_id", ondelete="CASCADE"),
            nullable=False,
        ),
        sa.Column(
            "user_id",
            postgresql.UUID(as_uuid=True),
            sa.ForeignKey("users.user_id", ondelete="CASCADE"),
            nullable=False,
        ),
        sa.Column("rating", sa.Integer, nullable=False),
        sa.Column("comment", sa.Text, nullable=True),
        sa.Column("created_at", sa.TIMESTAMP(timezone=True), server_default=sa.text("now()"), nullable=False),
        sa.CheckConstraint("rating >= 1 AND rating <= 5", name="ck_scenario_reviews_rating"),
        sa.UniqueConstraint("user_id", "scenario_id", name="uq_scenario_reviews_user_scenario"),
    )


def downgrade() -> None:
    op.drop_table("scenario_reviews")
    op.drop_table("bookmarks")
```
Match column types/defaults exactly to `db/models/bookmark.py` and `db/models/review.py` — do not invent new fields.
